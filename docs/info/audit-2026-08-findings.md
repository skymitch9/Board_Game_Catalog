## Summary

- **24 confirmed findings** — 0 critical · 0 high (2 reviewed-high, both
  adjusted to medium in verification) · **13 medium** · **11 low**.
- **2 findings were refuted** in verification and are not listed here.
- **12 units reviewed**; 1 (`migrations`) came back clean.
- No finding is covered by an existing test, and none is waived in
  `KNOWN_ISSUES.md`.

The single loudest theme is **stale comments that contradict live behaviour**
(the estate-check "inert" comment over an `enforce` value; the CSP allowlist a
comment claims exists in `_headers` but does not; the "Access still in front"
vars after Access was deleted). None break the running system, but each is a
trap primed for the next debugger. The one finding with present-tense impact is
the **`/api/export.json` email leak** to any contributor-role user.

## What this audit did NOT cover

- **Static code review only.** Findings are read from the source at one commit;
  nothing was exercised against the live Worker, live D1, or a real browser.
  Reproduction steps are written, not run.
- **Edge / dashboard config outside the repo.** Whether a CSP is applied at the
  Cloudflare edge (finding #17), whether `GAMEUPC_API_KEY` is currently set
  (#11), and any dashboard-level secret or route config were NOT verified —
  they are not in the repo.
- **The out-of-unit render layer** for the `javascript:`-scheme URL finding
  (#19): whether the anchor render path sanitises `href` was not traced.
- **Cross-repo / estate-wide concerns** (the estate-auth contract shared across
  Workers, CORS/CSP posture across the estate, the two projects' Firestore
  rules) are handled by the estate-wide synthesis pass, not here.
- **Generated / vendored / dead code** — `node_modules`, `dist/`, build output
  under `apps/web/public/assets/`, and dead `worktree-agent-*` branches were
  out of scope by the harness definition.
- **Two reviewed findings were refuted** in verification and deliberately
  omitted; this doc lists only survivors.
- **No dependency / supply-chain audit** (no `npm audit`, no lockfile review)
  and **no performance profiling** were part of this pass.
